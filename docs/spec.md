# With×MEETS自動切り出しツール 設計書

## 1. システム概要
約30分のWith×MEETSファイルを入力とし、映像内に含まれる特定の「待機画面」画像をテンプレートとしてマッチングを行うことで、不要な待機時間を除いた「本編」および「AFTER」部分を自動的に切り出して保存するツール。
GUI（グラフィカルユーザーインターフェース）を備え、事前の設定確認、および解析結果のプレビュー確認（シーン切り替えタイミングでの再生・手動での秒数微調整）を行った上で安全に保存できる設計とする。

## 2. 動作要件
* **対象With×MEETS長:** 約30分
* **UI/UX:** GUIアプリケーションとして実装する。
  * **解析前:** 自動判定された処理モードと画面向き（縦/横）を画面に表示し、ユーザーが手動で変更（オーバーライド）可能とする。
  * **解析後:** 特定された切り出しタイミング（開始/終了地点）からプレビュー再生できる機能を提供。
  * **微調整機能:** 自動検出されたタイムスタンプ（開始・終了時間）を、ユーザーがGUI上のテキスト入力やシーカーを用いて秒単位で手動で微調整（修正）できる機能を提供する。
  * **承認と保存:** ユーザーがプレビューおよび微調整後の映像を確認し、承認（保存ボタンを押下）した後にファイル出力フローへ移行する。
* **アスペクト比対応:** 縦画面・横画面（解像度から自動判定、手動変更可）
* **処理モード:** 入力ファイル名から自動判別し、以下の3パターンに対応（手動変更可）。
  1. 本編 ＋ AFTER
  2. 本編のみ
  3. AFTERのみ

## 3. ディレクトリ構成とファイル規則

### 3.1. テンプレート画像の保存場所
判定に使用するテンプレート画像は、デフォルトで以下のディレクトリに格納されているものを使用する（GUI等で指定可能とする）。
* **配置場所:** `/mnt/h/MuMuSharedFolder/VideoRecords/wm/templates/`
* **縦画面用:** `vert_start.jpg`, `vert_mid.jpg`, `vert_end.jpg`
* **横画面用:** `hor_start.jpg`, `hor_mid.jpg`, `hor_end.jpg`

### 3.2. 入力ファイル名と自動判定ロジック
入力ファイル名に含まれる文字列パターンにより、処理モードを自動判定する。
* **本編 ＋ AFTER:** `YYYY-MM-DD(incl after).mp4` （`(incl after)` が含まれる）
* **AFTERのみ:** `YYYY-M-DD-after.mp4` （`-after` が含まれる）
* **本編のみ:** `YYYY-MM-DD.mp4` （上記どちらも含まれない場合）

### 3.3. 出力ファイル名と保存場所
* **保存場所:** 入力されたWith×MEETSファイルと同一ディレクトリ内に `trim` フォルダを自動作成し、その中に保存する。
* **出力ファイル名:** 入力ファイル名から日付部分（`YYYY-MM-DD` または `YYYY-M-DD`）を抽出し、以下の規則で生成する。
  * **本編ファイル:** `[入力元ディレクトリ]/trim/[日付]-main-trim.mp4`
  * **AFTERファイル:** `[入力元ディレクトリ]/trim/[日付]-after-trim.mp4`

## 4. 解析・判定ロジック

### 4.1. 画像マッチングの仕様
* **リサイズ処理:** 動画の解像度とテンプレート画像の解像度が異なる場合、マッチング処理の前にテンプレート画像を動画の解像度に自動リサイズする。
* **判定領域の制限:** 画面の上部・下部にはシークバーやヘッダー等のUIが表示されることがあるため、誤検出を防ぐために画面の中央領域（中央1/3など）を基準にしてテンプレートマッチング（`cv2.matchTemplate`）を行う。
* **類似度判定:** フレームごとの類似度スコアを算出し、閾値を設定して状態の遷移（待機画面中か、本編/AFTER中か）を判定する。

### 4.2. 各モードの切り替え位置判定規則
各テンプレートの検出状態（検出中 ＝ 類似度が閾値を上回っている、非検出中 ＝ 類似度が閾値を下回っている）の切り替わり時点を基準とする。デフォルトのオフセット（猶予時間）は0秒とし、ユーザーがプレビュー画面で必要に応じて調整する。

1. **本編 ＋ AFTER モード**
   * **構成:** `[開始待機画面 (Start)]` ➜ `[本編]` ➜ `[中間待機画面 (Mid)]` ➜ `[AFTER]` ➜ `[終了待機画面 (End)]`
   * **本編開始点:** `start` テンプレートが「検出終了（非検出になった）」瞬間
   * **本編終了点:** `mid` テンプレートが「検出開始」した瞬間
   * **AFTER開始点:** `mid` テンプレートが「検出終了」した瞬間
   * **AFTER終了点:** `end` テンプレートが「検出開始」した瞬間
2. **本編のみ モード**
   * **構成:** `[開始待機画面 (Start)]` ➜ `[本編]` ➜ `[終了待機画面 (End)]`
   * **本編開始点:** `start` テンプレートが「検出終了」した瞬間
   * **本編終了点:** `end` テンプレートが「検出開始」した瞬間
3. **AFTERのみ モード**
   * **構成:** `[中間待機画面 (Mid)]` ➜ `[AFTER]` ➜ `[終了待機画面 (End)]`
   * **AFTER開始点:** `mid` テンプレートが「検出終了」した瞬間
   * **AFTER終了点:** `end` テンプレートが「検出開始」した瞬間

## 5. フェイルセーフ（予期せぬエラー時の動作）
マッチング処理において、基準となる待機画面が検出できなかった場合はエラーで停止させず、以下のフォールバック処理を行う。
* **開始地点（本編開始、またはAFTER開始）が検出されなかった場合:** 該当パートの開始時刻を「0:00（動画の先頭）」として扱う。
* **終了地点（本編終了、またはAFTER終了）が検出されなかった場合:** 該当パートの終了時刻を「動画の終端」として扱う。

## 6. 使用技術
* **言語:** Python
* **GUI・映像再生:** PySide6 / PyQt6（動画再生プレイヤー、タイムスタンプ微調整UIの構築）
* **画像処理・映像解析:** OpenCV (`cv2`)
* **切り出し処理:** FFmpeg (`subprocess`経由で実行、厳密な秒数での切り出しを行うため**再エンコードを伴う切り出し**を実行する)
  * 例: `ffmpeg -ss [開始秒] -to [終了秒] -i [入力] -c:v libx264 -crf 18 -preset veryfast -c:a aac [出力]`

## 7. 処理フロー

### 7.1. 初期化・ユーザー設定フェーズ
1. **ファイルの読み込み:** GUI上でユーザーが指定したWith×MEETSファイルパスを取得する。
2. **モード/アスペクト比自動判定:** ファイル名から「処理モード」を、解像度から「画面向き（縦/横）」を仮決定する。
3. **ユーザー設定確認:** 判定結果をGUIに表示。ユーザーは必要に応じて設定を手動で上書きし、「解析開始」ボタンを押下する。
4. **テンプレートのロード:** 確定した設定に基づき、テンプレート画像を読み込み、必要に応じて動画解像度に合わせてリサイズする。

### 7.2. 解析フェーズ（タイムスタンプの特定）
With×MEETSを一定間隔（適宜フレームを間引いて高速化）で走査し、画面中央領域とテンプレート画像との類似度を計算して切り替えポイント（タイムスタンプ）を特定する。
※検出に失敗した箇所は、第5項（フェイルセーフ）の規則に従って補完する。

### 7.3. プレビュー・承認フェーズ
1. **プレビュー表示:** 解析完了後、GUI上にプレイヤー画面を表示する。
2. **タイミング確認・微調整:** 「本編開始」「本編終了」「AFTER開始」「AFTER終了」それぞれのタイムスタンプから再生を開始できるボタンを提示し、ユーザーが実際の映像切り替わりを目視確認する。また、入力ボックスやスライダー等を用いて切り出し時間を手動で調整できるようにする。
3. **承認:** ユーザーが問題ないと判断し、「保存」ボタンを押下することで次フェーズへ進む。

### 7.4. 切り出し・出力フェーズ
1. **ディレクトリ作成:** 入力ファイルと同階層に `trim` フォルダが存在しない場合は作成する。
2. **切り出し実行:** 確定・微調整されたタイムスタンプを使用し、FFmpegによる再エンコード切り出しコマンドを構築・実行する。
